# Chapter 4: Thresholds, Calibration and the Safety Operating Point

Chapter 3 ended with a classifier that silently used the default 0.5 cutoff to turn a continuous score into a decision. This chapter treats that cutoff as something to be designed rather than assumed, and turns the fitted model from Chapter 3 into a full operating policy: a threshold selected on validation data, a calibration check, a documented cost trade-off, and a decision rule that could be reproduced elsewhere.

The notebook [`chapter_4_thresholds_and_calibration.ipynb`](chapter_4_thresholds_and_calibration.ipynb) reproduces the chapter's walkthrough end to end. Running it top to bottom will:

- load the Chapter 3 fitted pipeline and the Chapter 2 data split (regenerating either automatically if missing, so this notebook runs on its own);
- carve out a dedicated fit/calibration split so threshold and calibration decisions never touch the test set;
- inspect the safe/unsafe score distributions before touching a threshold at all;
- sweep the decision threshold and watch precision, recall, specificity, false-positive rate and false-negative rate move;
- build precision-recall and ROC curves, and show numerically why ROC-AUC can look reassuring while precision collapses on rare-event traffic;
- select thresholds three different ways: maximizing F2, minimizing an explicit false-positive/false-negative cost (with a sensitivity analysis across cost ratios), and satisfying a minimum-recall constraint;
- build reliability diagrams and compute Brier score, log loss and expected calibration error;
- fit and compare Platt (sigmoid) and isotonic calibration on held-out data;
- show how a production base-rate shift changes precision even when the classifier itself has not changed;
- implement a three-way allow/review/block policy and check it against a review-capacity constraint;
- finalize the chosen model, calibrator and threshold, evaluate once on the untouched test set, and bootstrap a confidence interval around the reported recall; and
- save the resulting model, calibrator, threshold table and metrics report as versioned artifacts.

## Data and dependencies

This notebook depends on artifacts from [Chapter 2](../Chapter%202) (the processed data split) and [Chapter 3](../Chapter%203) (the fitted baseline pipeline). If they are not already on disk, the notebook regenerates them itself using the same procedures, so cloning the repo and running only this notebook still works.

## Running it

From the repository root:

```bash
pip install -r requirements.txt
jupyter notebook "Chapter 4/chapter_4_thresholds_and_calibration.ipynb"
```

No GPU is required. The generated `models/`, `config/` and `reports/` folders (the fitted pipeline, calibrator, safety policy config, threshold table and test metrics) are written under the `Chapter 4/` directory when you run it, and are gitignored since they are regenerated by the notebook rather than checked in.
